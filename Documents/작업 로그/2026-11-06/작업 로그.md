## [작업] 구글 OAuth 소셜 로그인 시 계정 선택 창(select_account) 강제 활성화 및 Vercel SPA 라우팅 설정

### 1. 지시 사항 (User Request)
- 구글 소셜 로그인 시 기존 크롬 브라우저 로그인 세션 또는 이전 로그인 계정으로 계정 선택 창 없이 자동 로그인되는 현상 해결 요청.

### 2. 목적 및 배경 (Purpose & Context)
- Google OAuth 표준 규격상 `prompt` 옵션을 지정하지 않을 경우, 브라우저에 이미 로그인된 구글 세션이 존재하면 계정 선택 화면을 생략하고 자동으로 즉시 인가(Redirect)를 진행함.
- 이로 인해 다중 구글 계정(예: `forwork1817@gmail.com` vs `phj20030707@gmail.com`)을 보유한 사용자가 원하는 계정을 직접 선택하여 로그인하지 못하고 이전 계정으로 자동 로그인되는 사용성 저해 문제가 발생함.
- 또한 Vercel 배포 환경에서 서브 라우트 직접 접근 시 404를 방지하기 위한 `vercel.json` SPA rewrite 설정이 누락되어 있었음.

### 3. 수정 대상 및 규모 (Scope & Impact)
- `src/pages/LoginPage.tsx` (+4 라인): `signInWithOAuth` 옵션 내 `queryParams: { prompt: 'select_account', access_type: 'offline' }` 추가.
- `src/pages/SignupPage.tsx` (+4 라인): `signInWithOAuth` 옵션 내 동일 `queryParams` 설정 추가.
- `vercel.json` (신규 생성): SPA 전체 라우트 rewrite 규칙 구성.

### 4. 세부 구현 내용 (Implementation Details)
- Supabase Auth의 `signInWithOAuth({ provider: 'google', options: { queryParams: { prompt: 'select_account', access_type: 'offline' } } })` 설정을 적용하여, 구글 로그인 버튼 클릭 시 구글 계정 선택 모달(Account Picker)이 무조건 강제 호출되도록 구현.
- 사용자가 여러 구글 계정 중 원하는 계정을 자유롭게 선택하거나 "다른 계정 사용"으로 로그인할 수 있도록 보장.

### 5. 실수 방지 및 기술 주의사항 (Lessons & Anti-Patterns)
- Google OAuth에서 `prompt: 'select_account'`를 지정하지 않으면 브라우저 자동 승인이 기본값으로 작동하므로 소셜 로그인 연동 시 반드시 명시해야 함.
- Vite + React Router 배포 환경에서는 `vercel.json`에 `{"rewrites": [{"source": "/(.*)", "destination": "/"}]}`가 누락되면 새로고침 시 404가 발생하므로 배포 구성에 필수 포함.

### 6. 무결성 검증 (Verification)
- `npx tsc -b` 실행 결과: 오류 0건 (성공).
- 기존 사용자 코드 및 로직 훼손 없이 Surgical Edit 완료.

### 1. 지시 사항 (User Request)
- 타이프라이터 모드 시 입력 커서가 뷰포트 하단에 치우치는 문제를 해결하고, 문서의 첫 줄부터 마지막 줄까지 항상 뷰포트 정중앙(50%)에 유지되도록 개선 요청.

### 2. 목적 및 배경 (Purpose & Context)
- 기존에는 `paddingTop: 1rem`, `paddingBottom: 50vh`로 상단 여백이 없어 문서 상단부(1~15줄) 작성 시 스크롤 공간 부족으로 커서가 중앙으로 이동하지 못하고 화면 하단으로 밀려남.

- 과거 임시 span 태그 삽입 및 `selection.removeAllRanges()` 재지정 방식이 한글(IME) 조합 분리 현상을 유발할 위험이 있었음.

### 3. 수정 대상 및 규모 (Scope & Impact)
- `src/components/workspace/writingspace/MainEditorCanvas.tsx` (Lines 48-56):
  - `paddingTop`과 `paddingBottom` 모두 `typewriterMode ? 'calc(50vh - 3rem)' : ...` 대칭 가상 여백 적용 및 부드러운 패딩 트랜지션 추가.
- `src/components/workspace/WritingSpace.tsx` (Lines 1, 168-177, 549-605):
  - `useCallback` 및 `typewriterRafIdRef` 도입.
  - DOM/Selection 비파괴적 좌표 측정(`getClientRects()` 및 부모 노드 fallback) 및 `requestAnimationFrame` + `scrollBy({ top: diff, behavior: 'instant' })` 적용.
  - 허용 오차(Tolerance 8px) 적용으로 동일 행 타이핑 시 불필요한 미세 흔들림 제거.

- 텍스트 범위 드래그 선택 중(`!selection.isCollapsed`)에는 스크롤을 무시하여 드래그 시야 요동 방지.
- 한글 IME 입력 중 글자 분리가 발생하지 않도록 Selection DOM을 일절 건드리지 않고 스크롤 컨테이너의 `scrollTop` 변위만 정밀 계산 반영.

### 5. 실수 방지 및 기술 주의사항 (Lessons & Anti-Patterns)
- `contenteditable` 타이프라이터 구현 시 임시 DOM 요소를 삽입하거나 Selection range를 재지정하면 한글 자모가 분리되므로 반드시 순수 좌표 계산 방식(`getClientRects()`)만 사용해야 함.
- 타이핑 중 빠른 연속 입력 시에는 `smooth` 스크롤 큐가 지연을 유발하므로 `instant` 스크롤이 필수적임.

### 1. 지시 사항 (User Request)
- 타이프라이터 모드 활성화 시 제목 위쪽에 생기는 거대한 상단 빈 공간(여백)을 제거하고, 정상적인 문서 배치 상태에서 자연스럽게 중앙 고정되도록 수정 요청.

### 2. 목적 및 배경 (Purpose & Context)
- 문서 첫 줄부터 강제로 화면 50%에 맞추기 위해 캔버스 전체에 `paddingTop: calc(50vh - 3rem)`을 주었던 것이 제목 위에 화면 절반 크기의 공백을 유발함.

### 3. 수정 대상 및 규모 (Scope & Impact)
- `src/components/workspace/writingspace/MainEditorCanvas.tsx` (Lines 48-56): `paddingTop`을 `'1rem'`으로 원복하고 `paddingBottom`만 `calc(50vh - 3rem)` 가상 여백 유지.

### 4. 세부 구현 내용 (Implementation Details)
- 문서 시작 시 제목 및 상단 문단이 상단 툴바 바로 아래 깔끔하게 위치함.
- 커서가 화면 중앙(50%)보다 위에 있을 때(`diff < 0` 및 `scrollTop === 0`)는 스크롤하지 않고 자연스러운 입력 유지.
- 커서가 화면 중앙에 도달하거나 그 아래로 내려가려고 할 때만 `scrollTo`로 화면을 끌어올려 정확히 중앙에 커서 고정.
- 문서 끝까지 작성할 수 있도록 하단 가상 여백은 온전히 보존.

### 5. 실수 방지 및 기술 주의사항 (Lessons & Anti-Patterns)
